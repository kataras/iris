# Internationalization

`middleware/i18n` is fully in-framework: no third-party dependency, no external message compiler. A catalog is loaded once at startup, a middleware decides each request's language, and handlers translate through the context.

The minimal setup (catalog, both middlewares, `GetLocale`/`GetMessage`) is in [middleware-reference.md](./middleware-reference.md). This file covers the rest: the loader variants, detection order, the full message syntax and view integration.

```go
import "github.com/kataras/iris/v14/middleware/i18n"
```

## Loading Translations

The **first** language in the list is the default. Omit the list entirely and languages are discovered from the paths.

```go
locales := i18n.New()
if err := locales.Load("./locales/*", "en-US", "el-GR"); err != nil {
    panic(err)
}
locales.SetDefault("en-US") // reorder after loading, returns false if unknown
```

Language codes come from the directory name or the file name, so both layouts work:

```
locales/el-GR/messages.yml
locales/el-GR.yml
```

The file extension selects the parser: `.yaml`/`.yml` (default), `.json`, `.toml`/`.tml`, `.ini`. Nested keys flatten with dots, so `user: {name: ...}` is read as `user.name`; INI sections behave the same way.

### Loader variants

| Method | Source |
|--------|--------|
| `Load(globPattern, languages...)` | Files on disk |
| `LoadFS(fileSystem fs.FS, pattern, languages...)` | An `fs.FS`, including `embed.FS` |
| `LoadKV(langMap LangMap, languages...)` | In-memory maps |
| `LoadAssets(assetNames, asset, languages...)` | A generated asset function pair |

Embedding makes the binary self-contained:

```go
//go:embed locales/*
var localesFS embed.FS

locales := i18n.New()
locales.LoadFS(localesFS, "locales/*", "en-US", "el-GR")
```

`LangMap` is an alias for `map[string]map[string]any`, so `LoadKV` takes language code → key → value.

### Loader options

`locales.Loader` is a `LoaderConfig`. Set it **before** any `Load` call.

```go
locales.Loader.Strict = true    // fail when a language has no file at all
locales.Loader.Left = "[["      // template delimiters, default "{{"
locales.Loader.Right = "]]"     //                      default "}}"
locales.Loader.Funcs = func(l locale.Locale) template.FuncMap {
    return template.FuncMap{"upper": strings.ToUpper}
}
```

Also available: `DefaultMessageFunc` and `PluralFormDecoder`.

A missing key returns an empty string by default, which hides typos. Make them visible:

```go
locales.SetDefaultMessageFunc(func(langMatched, key string, args ...any) string {
    return "!MISSING:" + key + "!"
})
```

## Detecting the Language

Two middlewares with different jobs. Register both, in this order.

`NewRouter` runs **before routing** and rewrites the request: it strips a `/el-GR/...` path prefix or an `el.example.com` subdomain, sets the language cookie (with `Domain: ctx.Domain()` and `SameSite=Lax`), overwrites the request's `Accept-Language` header with the matched tag and then calls `InjectFunc`. Because it rewrites the path, your routes stay language-free.

```go
app.UseRouter(i18n.NewRouter(locales, i18n.RouterOptions{
    Cookie:    "lang",
    Subdomain: true,
    InjectFunc: func(ctx iris.Context, tag language.Tag) {
        accesslog.GetFields(ctx).Set("lang", tag.String())
    },
}))
```

`NewHandler` runs per matched route and resolves the locale for the context:

```go
app.Use(i18n.NewHandler(locales, i18n.HandlerOptions{
    URLParameter: "lang",   // ?lang=el-GR
    Cookie:       "lang",
    Subdomain:    true,
    ExtractFunc: func(ctx iris.Context) string { // highest-priority custom source
        return ctx.Header("X-Language")
    },
}))
```

Resolution order, first match wins:

1. A language already set on the context (by `NewRouter` or `SetLanguage`)
2. `ExtractFunc`
3. `URLParameter`
4. `Cookie`
5. `Subdomain`
6. The `Accept-Language` request header
7. The default language

Matching is lenient: `el-GR`, `el-gr` and `el` all resolve to the same locale.

To set the language from code:

```go
i18n.SetLanguage(ctx, "el-GR")
loc := i18n.SetLocaleByLanguage(ctx, "el-GR") // same, returns the locale
```

## Translating in Handlers

```go
loc := i18n.GetLocale(ctx)           // locale.Locale
msg := loc.GetMessage("hi", "Iris")

msg := i18n.GetMessage(ctx, "hi", "Iris") // one-liner equivalent
```

`locale.Locale` is:

```go
type Locale interface {
    Index() int
    Tag() *language.Tag // pointer
    Language() string
    GetMessage(key string, args ...any) string
}
```

Messages use printf verbs, including indexed ones so translations can reorder arguments:

```yaml
hi: "Hi %s!"
visits: "%[2]s visited %[1]d times"
```

## Pluralization and Variables

### Plural forms

A message whose value is a map is a plural set. The **first** `GetMessage` argument is the count and also feeds the printf verbs.

```yaml
apples:
  zero: "no apples"
  one: "one apple"
  two: "two apples"
  other: "%d apples"
  "=42": "the answer in apples"
  "<10": "a few apples (%d)"
  ">100": "lots of apples (%d)"
```

```go
loc.GetMessage("apples", 3) // "3 apples"
```

Calling a plural message with no count returns a descriptive error string rather than panicking, so a missing argument surfaces in the response instead of taking the process down.

### Variables

`Vars` declares reusable fragments referenced as `${Name}`, either top-level for the whole file or per message:

```yaml
Vars:
  - Minutes:
      one: "minute"
      other: "minutes"

ago: "%[1]d ${Minutes} ago"

custom:
  Text: "%[1]d ${Points} earned"
  Vars:
    - Points:
        one: "point"
        other: "points"
```

The same argument that selects the message's plural form also selects each variable's form.

### Template messages

A value containing the loader's delimiters is parsed as `text/template`. The first `GetMessage` argument becomes the template data, the reserved key `PluralCount` selects the plural form, and a per-locale `tr` function is available inside the template.

```yaml
welcome: "Welcome {{.Name}}, you have {{.Unread}} unread"
cart:
  one: "{{.Count}} item in your cart"
  other: "{{.Count}} items in your cart"
```

```go
loc.GetMessage("welcome", map[string]any{"Name": "Makis", "Unread": 4})
loc.GetMessage("cart", map[string]any{"PluralCount": 3, "Count": 3})
```

## Views

Two shapes, depending on whether the template needs the request's language or an arbitrary one.

A static function that takes the language explicitly works for any locale:

```go
templates.AddFunc("tr", func(lang, key string, args ...any) string {
    if loc, ok := locales.GetLocale(lang); ok {
        return loc.GetMessage(key, args...)
    }
    return key
})
```

```gotemplate
{{ tr "el-GR" "hi" "Iris" }}
```

A per-request closure passed as view data binds the current locale:

```go
func page(ctx iris.Context) {
    loc := i18n.GetLocale(ctx)
    view.Render(ctx, "index.html", "", map[string]any{
        "tr": loc.GetMessage,
    })
}
```

```gotemplate
{{ call .tr "hi" "Iris" }}
```

View engine setup is in [middleware-reference.md](./middleware-reference.md); engines themselves live in `github.com/iris-contrib/views`.

## Inspecting the Catalog

Useful for a language switcher or a diagnostics endpoint:

```go
locales.Loaded()                         // bool
locales.Tags()                           // []language.Tag, in load order
locales.TryMatchString("el")             // (language.Tag, index, bool)
locales.GetLocale("el-GR")               // (locale.Locale, bool)
locales.GetLocaleByIndex(0)              // (locale.Locale, bool)
locales.GetDefaultLocale()               // locale.Locale
locales.Reset(loader, "en-US", "el-GR")  // reload at runtime
```
